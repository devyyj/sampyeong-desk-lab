# 게시글 양식 통합(일반 글 + 활동 기록) 설계

- 작성일: 2026-10-17
- 브랜치: `feature/feed-activity-merge`
- 선행: `2026-10-16-feed-activity-merge-design.md`(활동 기록을 게시글의 한 종류로 이관, 0006·이관·0007 적용 완료)

## 1. 목적

작성 화면의 "일반 글 | 활동 기록" 구분을 없애고 **양식을 하나로** 만든다. 활동 종류는 태그로, 모임 날짜·시즌은 선택 입력으로 받는다.
글 종류(`kind`)라는 개념 자체를 없애, 모든 글이 같은 모양·같은 규칙을 따른다.

## 2. 사용자 결정 사항

| 항목 | 결정 |
|---|---|
| 양식 | 일반 글 양식 하나(사진 + 내용) |
| 활동 종류 | 태그. 내용 아래 별도 태그 칸에서 입력(Enter·쉼표로 추가, `#방탈출` 칩으로 표시, 예시 칩) |
| 태그 개수 | 여러 개, 최대 5개 |
| 모임 날짜·시즌 | 선택 입력. 입력한 경우에만 카드에 표시 |
| 제목 | 없앤다. 기존 활동 기록 92건의 제목은 본문 첫 줄로 옮긴다 |
| 사진 공개 범위 | 모든 글의 사진을 회원 전용(비공개 버킷 + signed URL) |
| 피드 필터 칩 | 없앤다. 카드의 태그를 누르면 그 태그 글만 모아 본다 |

## 3. 데이터 모델

### 3.1 마이그레이션 0008 (`0008_post_tags.sql`, 한 트랜잭션)

1. `posts.tags text[] NOT NULL DEFAULT '{}'` 추가, `CHECK (cardinality(tags) <= 5)`, GIN 인덱스(`tags @> ARRAY[...]` 조회용).
2. 기존 활동 기록 이관: `tags = ARRAY[activity_type]`, `content = title || E'\n' || content` (`kind = 'activity'`인 행).
3. `posts_kind_fields` CHECK와 `posts_kind_created_at_idx` 인덱스를 지운다(제목·종류가 없는 글도 날짜·시즌을 가질 수 있게).

`season_id`·`activity_date`·`source_key`는 그대로 쓴다(선택 칼럼).
`kind`·`title`·`activity_type` 칼럼은 앱에서 더 이상 쓰지 않고, 되돌릴 여지를 두기 위해 **0009 정리 단계에서 지운다**(옛 `activities` 계열 테이블·`comments.activity_id` 삭제와 함께).

적용 전 `posts`·`post_images`를 JSON으로 백업한다. 공유 운영 DB라 적용 직전에 확인을 받는다.

### 3.2 태그 규칙 (`src/lib/tags.ts`)

- 앞뒤·중복 공백 정리, 앞의 `#`는 떼고 저장, 1~20자, 같은 태그는 한 번만, 최대 5개.
- 예시: 방탈출 · 정기 모임 · 점심 · 저녁.
- 클라이언트(칩 입력)와 서버 액션(최종 검사)이 같은 함수를 쓴다.

### 3.3 사진

- 모든 글의 사진은 비공개 버킷 `activity_photos`에 올리고 회원에게만 signed URL로 보여준다(버킷 이름은 이관 사진 197장을 옮기지 않으려고 그대로 쓴다. 코드에서는 `POST_PHOTOS_BUCKET` 상수 하나로만 가리킨다).
- 업로드 경로 규칙은 지금과 같다(`${userId}/${uuid}.${ext}`, 서버 검사).
- 운영의 기존 일반 글은 1건이고 사진이 없어 옮길 파일이 없다. 공개 버킷 `post_images`는 더 이상 쓰지 않는다.

## 4. 앱 변경

### 4.1 작성·수정 양식 (`PostForm`)

```
 취소          새 게시글          게시하기
 [📷 사진 0/10] [미리보기]…
 내용   [ 내용을 입력하세요              ]
 태그   [#방탈출 ×] [#스컬킹 ×] [ 태그를 입력하세요 ]
        예시 (방탈출)(정기 모임)(점심)(저녁)        2/5
 모임 날짜 [          ] (선택)   시즌 [선택 안 함 ▾]
```

- 종류 전환·제목 칸을 없앤다. 수정 화면도 같은 양식이다.
- 날짜·시즌은 비워 둘 수 있다(기본값 없음). 시즌은 날짜와 별개로 고를 수 있다.

### 4.2 카드·상세 (`PostCard`)

- 작성자 줄의 날짜는 하나: 모임 날짜가 있으면 모임 날짜(`relativeDay`), 없으면 작성 시각(`relativeTime`).
- 시즌이 있으면 작성자 줄 아래에 시즌 칩.
- 태그는 본문 아래 `#방탈출` 링크 칩으로 보여주고, 누르면 `/?tag=방탈출`.
- 사진: 회원은 썸네일(피드)·캐러셀(상세), 비회원은 모든 글에서 "로그인하면 사진 N장을 볼 수 있어요".

### 4.3 피드 (`/`)

- 필터 칩 줄을 없앤다. 최신순 무한 스크롤(10건)은 그대로 둔다.
- `/?tag=X`면 그 태그 글만 보여주고, 제목 줄에 `#X`와 "전체 보기" 링크를 둔다.
- 예전 주소 `/?kind=…`는 무시하고 전체를 보여준다. `/activities` 리디렉트 목적지는 `/`로 바꾼다.

### 4.4 제거

`kind` 관련 코드(`feed-filter`의 kind, `FeedFilterChips`, `bucketForKind`, `activity-fields`, `activity-types`의 종류 표시), 공개 버킷 URL 함수 `postImagePublicUrl`의 게시글 사용처.

## 5. 테스트

- 단위(TDD): 태그 정리·검사, 0008 이후 피드 조회(태그 필터, 모든 사진 서명·비회원 잠금), 카드(날짜 하나·시즌·태그 링크), 양식(태그 칩 추가·삭제·5개 제한·예시, 날짜·시즌 선택), 액션(태그·날짜·시즌 저장, 비공개 버킷 검사).
- E2E(실제 DB·Storage): 사진+태그+날짜로 글 작성 → 사진이 비공개 버킷에 올라가고 회원에게 보이며 비회원에게는 안내만 → 태그를 눌러 모아 보기 → 날짜·시즌 없는 글에는 칩이 없음 → 수정·삭제 권한.
